# Sungrow iSolarCloud worker

Official plaintext monitoring API for an approved developer application and an owner-authorized OAuth token. Supply configuration `appKey`, secrets `accessKey` and `accessToken`, and the corresponding regional gateway. Europe, China, international/Hong Kong, Australia and India HTTPS gateways are declared in the manifest. API access remains conditional on Sungrow application approval, owner consent and the purchased/assigned monitoring permissions. This worker consumes a supplied token; it does not claim an integrated authorization or token-renewal flow.

Implemented: paged residential plant/device discovery; type 14 energy storage inverter live measuring points; minute-level grid history. Each returned device must match its authorized `ps_key` and serial. Official point IDs are 13003 PV DC W; 13141 SOC; 13138 V; 13139 A; 13143 battery Celsius; 13150 discharge W minus 13126 charge W; 13149 purchased W minus 13121 feed-in W; 13119 load W. Grid import and battery discharge are positive. Missing/null fields are missing; malformed or out-of-range fields are invalid. The API explicitly returns minimum units (W, V, A), regardless of display scaling in the portal. The energy-storage SOC point is treated as percent, with a 0–100 bound.

Set the plant's IANA `deviceTimeZone` for observation timestamps and history. Local timestamps with absent/invalid time zones, DST gaps or DST folds remain unknown; the worker does not invent UTC timestamps. History uses the documented three-hour maximum per request and at most seven days per operation. The vendor excludes the current day from this history API; such requests return incomplete history. Empty blocks, invalid points and conflicting duplicates also mark it incomplete. Vendor live data refreshes about every five minutes.

Production requests use the SDK CloudHttpClient, approved origins and no redirects. An injected HttpClient is available for the real framed-worker HTTP fixture and still validates configured origins.
