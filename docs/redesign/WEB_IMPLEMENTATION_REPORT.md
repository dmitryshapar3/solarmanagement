## Shared controls and behavior

`Components/Ui/` contains `UiButton`, `UiCard`, `UiNumber`, `UiBearing`, `UiSelect`, `UiSwitch`, `UiState`, `UiModal`, `PageHeader`, `StatusPill`, `BrandMark`, icons, formatting, form-state and unsaved-navigation helpers. `Components/Charts/` contains data-driven SVG production/export/readings/timeline/range components. Sidebar and drawer use the same route model as the Razor account shell. Tables scroll internally on narrow screens; split panes, device cards and template cards stack at 390px. Each roof's SVG compass binds the real bearing to its needle, N/E/S/W presets, native keyboard-operable slider and numeric entry.

The token generator writes `wwwroot/css/tokens.css` and `mobile/src/ui/theme/tokens.ts` from the shared design source. `node scripts/generate-design-tokens.mjs --check` verifies generated outputs. Fonts and logos are local assets; no runtime font/CDN dependency was introduced.

Installation settings and automation forms disable mutation controls for read-only members while retaining readable details, personal Appearance and navigation. Save, weather testing, rule enable/disable and deletion recheck current permissions before server work. Draft weather results are fenced after coordinates change or are discarded; tests verify no saved settings are changed by a probe.

Controls retain keyboard focus and accessible names. Closing a gallery dialog restores its opening-button focus. Forms preserve raw invalid numeric text and block save until valid; Discard resets the raw fields as well as the saved model. General Refresh controls were removed in keeping with the earlier request. Purposeful Test connection, Check prices and uncertain-command result recovery actions remain, because they perform distinct domain operations.

The connection dialog uses native focus trapping. Escape follows the same guarded close handler as the Close button, preserving unsaved drafts until explicit Discard and blocking closure during a pending operation. Paste reads the clipboard only on an explicit secret-field action; a delayed result cannot restore a credential after its field, action, value, busy state or component lifetime changes. Selecting a device atomically saves its optional host display name with the binding, preserving provider identity, capabilities and automation associations. Discovery reads the canonical `metadata.capabilities.canSwitch` contract; live availability is not inferred from a successful discovery. Trial quota disables only new socket additions, retaining existing selected-device replays and inverter selection.

Each saved service card opens its own settings, connection check or discovery dialog. These actions use the selected saved instance and keep secrets on the server; opening or checking never saves a draft or switches a device. Installation-scoped integration notifications reload the displayed status facts through the fenced query scope after connection changes, without a general Refresh button.

Unknown browser routes render a public brand/card/footer without private installation services. This avoids constructing the tenant-dependent app layout before an installation is bound and keeps the 404 page available to anonymous visitors.

Switch permission is fail-closed while command receipts or capability metadata are unavailable. Recovery resolves only catalog metadata; it sends neither device reads nor power commands. Unsupported devices remain disabled. Every awaited metadata/receipt result is checked against the current device generation, and command dispatch rechecks capability and unresolved receipts immediately before admission.

## Intentional differences from sample mockups

- The mockups' names, dates, models, tariffs, coordinates, wattages and balances are sample design content. Production screens use authenticated installation/account facts; missing facts stay unavailable/unknown and real zero remains zero.
- Production's actual trace and estimated range retain quality/provenance and gaps. Historical period estimates are labelled for the period; live observations retain their own timestamp. Satellite and weather sources show their actual attribution.
- Market RCE uses raw signed market quarters. Money and deposit credit retain the saved contract policy. Missing market prices do not become zero or disappear simply because no export measurement exists for that hour.
- Device on-duration and activity totals disclose partial observation coverage. Provider acknowledgement does not imply an observed physical switch. Unsupported switching remains unavailable even if the device itself is online.
- Connection forms come from installed signed descriptors. Unknown manufacturers, absent descriptors, unconfigured OAuth/Apple/SMS and unavailable providers are handled honestly rather than replaced by sample services. Technical pin identifiers live in support/operator details.
- Account-sensitive operations use actual fresh-proof and confirmation steps; web billing presents verified plan facts and directs native purchase management appropriately. Sample App Store prices/savings are not web defaults.
- Additional settings, source, polling, tariff and operator controls needed to preserve existing functionality are included in the new visual system. These are functional extensions to the drawn happy paths.
- Missing/loading/offline/partial/denied/error states use the shared components. The access gate is styled consistently without extending entitlement validity or weakening server denial/revocation behavior.

### Production follow-up: circuit locale preservation

After the initial production cutover, genuine inverter snapshot updates exposed a locale defect: a Russian page's refreshed subtree switched to English while its unchanged navigation remained Russian. Translation lookup and presentation formatting depended on the background caller's ambient culture. The correction retains immutable format/UI cultures in each scoped `UiText`, supplies both exact culture names from `_Host` to `App` at circuit initialization, and uses that scope explicitly for translated templates, numbers, dates and numeric input. Regional formats such as `en-GB` are retained; personal/anonymous language forms still redirect to a fresh request/circuit. Background callbacks do not mutate ambient or global cultures, and no account, installation, entitlement, command or data semantics changed.

The Release build and the targeted locale/power/history/export/input suite passed **133 tests, 0 failed, 0 skipped**. Four new regressions cover concurrent Russian/English component scopes sharing actual snapshot events fired from an English worker; actual App initial-parameter lifecycle and the real card's `AsyncQueryScope` timer under an English renderer; the actual numeric input's decimal-comma parsing on an English event; and regional format retention/scope isolation without changing caller culture. Existing loaded-date and previous/next navigation assertions remain covered. Evidence: `/tmp/smartsolar-circuit-culture-tests.log` and private `circuit-culture-tests/circuit-culture.trx` under the release scratch directory. This is a later correction; the original 90-image manifest and its pre-cutover source/image provenance above remain unchanged.

### Production follow-up: first forecast load and measurement cutoff

A subsequent production check found that the first uncached Energy date could report an invalid-date error, while repeating the same request succeeded. A private reproduction using the actual `SolarProductionService` and `OpenMeteoSolarHistoryClient` with valid in-memory provider JSON and an advancing clock confirmed the cause: the weather client's captured retrieval time was slightly later than the service's earlier request-entry clock, so the calculator rejected the new model as future data. The correction evaluates the forecast against a fresh clock read after forecast/history I/O. Request-entry time still determines selected-calendar boundaries, completed/current hours, historical-query cutoff and rejection of later observations; the domain future-model guard is unchanged. No stored observations, site calibration, integration configuration or command state is changed.

Four new regression cases exercise first uncached today/previous-day reads through the actual weather client, slow I/O without moving measured-energy/hour cutoffs, and genuine future-model rejection. Final targeted/full gate receipts for this narrow correction are recorded separately by the release coordinator; the earlier locale suite and 90-image provenance remain unchanged.

### Production follow-up: Home estimate event clock

A later genuine production screenshot showed a freshly updated Home nowcast temporarily replaced by “Expected now —” and a waiting-for-fresh-data notice. The cause was presentation timing: Home supplied its own timestamp captured before the weather worker's newer estimate event. Although the card refreshed its internal clock on that event, the supplied parent timestamp took precedence, so the valid new estimate briefly appeared to come from the future. Home now lets the card use its existing event/timer clock; the optional explicit timestamp remains available for deterministic callers. Model, measurement, device provenance, future-data, staleness, alignment and nighttime comparison guards are unchanged.

Two SQL-backed regressions mount the actual Home page, publish a parent inverter snapshot, then advance the clock and invoke the real estimate service without firing parent timers or another inverter/device event. Both positive expected power and genuine zero disappeared before the correction; the corrected card retains the newly published value. Existing actual card cases still reject genuinely future estimate/source timestamps. The targeted gate receipt is recorded separately by the release coordinator; the original 90-image manifest and its source/image provenance remain unchanged.
